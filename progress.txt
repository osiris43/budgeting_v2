## Codebase Patterns
- `create_app()` calls `_check_ollama()` which requires a running Ollama instance — tests must patch `app._check_ollama` and set `DATABASE_URL=sqlite://` env var before importing `create_app`
- Use `setup.cfg` with `[flake8] max-line-length = 120` and `extend-ignore = E203` to match existing code style (pyproject.toml sets ruff line-length=100, but many lines are up to ~120)
- CLI commands are registered via `register_cli(app)` in `app/cli.py` — test with `app.test_cli_runner(mix_stderr=False)`
- Test isolation: use an autouse fixture that drops/recreates all tables between tests (savepoints don't work reliably with SQLite in-memory)
- Amounts are stored as integer cents (`amount_cents`); positive = expense, negative = credit/refund
- `MerchantRule` has a composite unique constraint on (pattern, detail_pattern) — same pattern can exist with different detail_patterns
- `apply_rules` uses two-pass matching: specific rules (with detail_pattern) first via `re.search`, then fallback rules (detail_pattern IS NULL)
- `base.html` has a `{% block scripts %}` block before `</body>` — use for page-specific JS
- For XHR vs form POST dual-mode routes: check `request.headers.get("X-Requested-With") == "XMLHttpRequest"` to return JSON, otherwise redirect
- CSV import logic is in `_import_csv_file()` helper (returns a summary dict) — both `import-csv` and `process-statement` CLI commands use it
- To test PDF-related CLI commands, mock `pdfplumber.open` with a fake PDF object that has `.pages` returning fake page objects with `extract_text()`
